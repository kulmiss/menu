# Bug hunt, 17 November 2026 (website only)

Full bug hunt of the Menu SaaS website (kulmiss/menu). The Flutter app was not
touched, and the mobile API output is unchanged. Each fix is its own small PR
into `develop`, with a test that fails before the fix and passes after, and a
filled-in checklist. Decisions are in QUESTIONS.md #196–#204.

## How it was tested

- The demo data (`DemoSeeder`), plus a new self-signed-up restaurant on the
  Free plan with emoji, Amharic, decimal prices, very long names and HTML/script
  text in every field. A test restaurant with 523 dishes, one with 0 dishes,
  one in style D, and one with photos off.
- Real Chromium (Playwright) scripts that record console errors, **CSP
  violations**, page errors, failed requests, pages wider than the screen,
  broken images, clipped text, overlapping text, and tap targets under 44 px.
  Run as guest, Owner, Manager, Staff and Super Admin, at 360 / 390 / 414 /
  768 / 1280 px, light and dark.
- API sweeps: 248 calls as one restaurant's owner against another
  restaurant's data, every write route as Staff and Manager, every
  `/platform` route as an owner.
- Backend: full Pest suite (629 tests) with a CI-like `.env`, Pint, Larastan.
  Frontend: Vitest, `tsc -b`, ESLint, Prettier, build, admin bundle budget.
  CI runs gitleaks, audits and the guest-menu Lighthouse budgets on every PR.

## Bugs (most serious first)

1. **Long dish name made admin pages wider than the phone** (menu editor
   794 px on a 390 px phone; dashboard, add-ons). The dish editor opened half
   off the screen. Fix: grids without columns never grow past their width.
   **#137**
2. **Super Admin → Mobile app crashed after clearing the banner**, locking the
   Super Admin out of every app setting. Fix: store "" not null, and repair
   null on read. **#139**
3. **CSV formula injection** in payments.csv, invoices.csv (restaurant names
   from self sign-up) and the menu export. Fix: one shared safe-cell helper;
   import undoes it. **#140**
4. **Admin controls smaller than 44 px on phones**, and every admin page
   scrolled sideways on 360 px phones. **#134**
5. **Appearance preview: tapping a dish crashed** (page error, dish never
   opened). **#133**
6. **CSP violation on every form page** (zod's eval probe). **#132**
7. **Branches page on phones**: address one letter per line. **#135**
8. **Style A: name ran under the price** on photo-less dishes. **#131**
9. **Very long words ran out of dish cards** and category headings off the
   screen. **#136** (merge after #131)
10. **Unreadable photo**: black crop box, no message. **#138**

Fixed earlier the same day: back-to-top on the right (#129) and the "Other
branches" list floating as a second order bar (#130).

**PDFs in any language (#142)**, after the owner's go-ahead: Amharic,
Arabic, Hebrew, Greek, Cyrillic and Vietnamese print correctly in every PDF;
emoji are left out cleanly. QUESTIONS #205.

## Left as they are (owner, 17 Nov) — QUESTIONS #204

- Two edits within 10 seconds while a guest has the menu open: the second
  shows only after the guest reloads twice.
- Guest pages can be framed by other sites (no `X-Frame-Options`).
- Chrome warns about the Appearance preview iframe (`allow-scripts` +
  `allow-same-origin`). A warning, not an error.

## What was NOT tested, and why

- **Real iPhone Safari, Samsung Internet, Firefox**: no devices or those
  browsers here. Everything ran in Chromium with phone sizes and touch.
- **Slow 3G and large text**: no network throttling or text zoom was run.
  Lighthouse in CI covers the guest menu on a throttled profile.
- **Lighthouse locally**: not run. CI ran it on the PRs that touch the guest
  page (#131, #133, #136): all passed the budgets.
- **Happy hour and promotion time windows** (before/during/after): checked
  that the scheduler refreshes pages each minute and that backend tests
  cover it; not clicked through at real times.
- **Every plan's limits** in the UI (only Free and Business were used), and
  expired or downgraded plans: covered by backend tests, not walked through.
- SMTP test (no mail server here), backups create/download, security log
  screen, landing page editor, help article editor, print materials and QR
  downloads: pages load with no console errors, but the actions weren't
  clicked through.
- The Flutter app itself.

## Merge order and steps (Laragon, port 8000)

Merge in this order (only #136 depends on another PR):

1. #131 → #136 (style A first, then long names)
2. #132, #133, #134, #135, #137, #138 (frontend, any order)
3. #139, #140, #142 (backend, any order)
4. this docs PR

Then in PowerShell:

```
cd C:\laragon\www\menu
git pull
cd frontend
pnpm install
pnpm build
cd ..\backend
composer install
php artisan optimize:clear
php artisan menu:refresh-pages --all
php artisan serve
```

Then press Ctrl+F5 in the browser. No migrations are needed.
