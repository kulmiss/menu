# Bug hunt — Menu Admin app (2026-11-17)

Everything below was checked on the app as it is after PR #24 (Help and the welcome tour). Every fix starts with a test that fails before it and passes after it. Each PR description has the 1–7 checklist.

## How it was tested

- **The real app in widget tests.** The whole app (router, gates, cache, every screen) runs against a fake server that can answer slowly, fail, go offline or answer 401/402/403/500. The tests tap through the screens like a person.
- **Devices.** The tests use a 360 dp phone, a landscape phone and a 10-inch tablet, in light and dark, with 130 % text (the largest the app allows).
- **Builds.** Each fix PR was built as a release APK (arm64, obfuscated) and a debug APK. The last PR was also built as an AAB. `tool/play_check.sh` checked the APK.
- **No emulator.** This cloud machine has no KVM, so no Android emulator runs here. Nothing was tried on a real phone. See "What I could NOT test".

## Bugs fixed (most serious first)

1. **Google Play would reject the app.** The merged manifest asked for `READ_MEDIA_IMAGES/VIDEO/AUDIO` (added by the open_filex package). Play's photo and video policy refuses these without a core need. It also asked for `CAMERA` and the advertising ID. All are removed. (PR 8/10)
2. **Leaving a screen while it saved threw "Using ref when a widget is about to or has been unmounted"**, and the list didn't show the change. This affected about 40 places: save, delete, invite, mark read, reorder, Was this helpful… (PR 2/10)
3. **Sign-in stuck on the logo forever** when the password was right but `/me` failed. (PR 3/10)
4. **Changed prices, Hide and sold out didn't show on the open screen** (Menu list, Home count), and page 2+ of All dishes stayed old. (PR 1/10)
5. **Camera access refused or an unreadable photo: uncaught crash**, with nothing on screen. (PR 4/10)
6. **Sign-out on a bad network took up to minutes.** (PR 3/10)
7. **A late `/me` answer signed the old account back in** on screen after signing out. (PR 3/10)
8. **Super Admin switch double tap** sent both values. (PR 2/10)
9. **Overflows and broken text at 130 %**: Insights with a long branch name (1,000 px off screen), "7 days" split letter by letter, big numbers and chart labels broken over lines; QR cards cut by 16 px; the sign-in links on a 360 dp phone. (PR 6/10 and 10/10)
10. **Delete my account** opened the privacy page at the wrong place (Play needs this link to work). (PR 5/10)
11. **Push shown in the app**: "Open" went to "not found" for a web link. (PR 5/10)
12. **Backing out of the crop screen** still uploaded the photo. (PR 4/10)
13. **The Play review prompt was never shown** (saves weren't counted). (PR 9/10)
14. **Ctrl+S saved twice**; a dish that failed to load had **no Try again**. (PR 5/10)
15. **Promotions special photo**: an upload error (offline) was not caught. (PR 2/10)
16. **News**: opening an announcement sent "read" again on every redraw. (PR 10/10)
17. `android/.kotlin` (Kotlin session files) was in git again. (PR 8/10)

## For the web chat (backend, not changed here)

- **Account deletion page.** Play asks for a web page where people can ask to delete their account and data. Today the app links to Privacy › "Your rights", which says to e-mail info@kulmiss.com. That is acceptable. A short page `/delete-account` would be clearer: the app name, the steps, what is deleted, what is kept and for how long. Then add a `links.account_deletion` value to `mobile/config` so the app can use it.
- No other backend bugs were found. Every push link the server sends opens an app screen.

## What I could NOT test, and why

- **Real phones and the Android emulator.** This machine has no KVM, so no emulator, and no USB phone. So I didn't measure crashes on a budget phone, scroll fps, memory, Android 8 vs 16, split screen, phone restart or low memory. Please run the checks in "Run it on your phone".
- **Real camera, gallery, crop screen and very large photos.** These were faked in tests. The code that shrinks photos was not changed.
- **Real push** from Firebase (received in the background or with the app closed, and the permission prompt). Messages were faked. The Firebase project and `google-services.json` are needed.
- **Biometric unlock, the Play in-app update and the review dialog** need a real phone and an app installed from Play.
- **Cold start, memory and fps** can't be measured without a device. Only the sizes below were measured.
- **iPhone**: not built here.

**Upload key (once):**

```
keytool -genkey -v -keystore ~/menu-admin-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

Then create `android/key.properties` (never commit it):

```
storePassword=…
keyPassword=…
keyAlias=upload
storeFile=/full/path/menu-admin-upload.jks
```

**Build and upload:**

1. Raise `version:` in `pubspec.yaml` (for example `1.0.0+2`). The number after `+` must go up for every upload.
2. Build the bundle:
   ```
   flutter build appbundle --release --obfuscate --split-debug-info=build/symbols --dart-define=API_BASE_URL=https://<your domain>
   ```
3. Upload `build/app/outputs/bundle/release/app-release.aab` in Play Console under Testing › Internal testing › Create release, and turn on Play App Signing.
4. Upload the symbols too (App bundle explorer › Downloads › Native debug symbols): zip `build/symbols`.

**Data safety answers:**

- **Collected:** name, e-mail address and user ID (account, needed). Photos (the restaurant's dish and logo pictures, needed). App interactions (optional, can be switched off). Crash logs and diagnostics (optional, can be switched off). Device or other IDs: the push token (needed for notifications).
- **Not collected:** location, contacts, messages, financial info, advertising ID.
- **Shared:** none (Firebase acts as a service provider).
- **Encrypted in transit:** yes.
- **People can ask for deletion:** yes, through the privacy page link.

**Content rating:** utility or productivity app for businesses. No violence, sex, gambling or drugs. Users don't talk to each other. Rated Everyone. Target audience: 18+.

## Run it on your phone

Merge #24 first, then the last PR of this bug hunt (it contains all ten). Or merge them in order, 1/10 → 10/10.

```
git checkout develop
git pull
flutter pub get
flutter gen-l10n
adb reverse tcp:8000 tcp:8000
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:8000
```

`adb reverse` lets the phone reach `php artisan serve` on your laptop over USB, without the Wi-Fi IP.

Please try these on the phone:

1. Change a price from the Menu list. The new price should show at once.
2. Add a dish photo and deny the camera once. You should see a message, not a crash. Then choose from the gallery.
3. Turn on flight mode and sign out. It should be quick.
4. Open Insights and QR codes with large text on.
5. Turn on dark mode and rotate the phone.
